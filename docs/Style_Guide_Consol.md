## 🎯 Зачем оформление в консоли

Консольный квест — это единственный жанр, где **вывод текста и есть графика**. Игрок не видит спрайтов и фона: он видит строки. Если все строки одинаковые, слитые и без структуры — игрок теряется в меню и не замечает, что изменилось после его действия.

**Три задачи оформления:**

| Задача | Как решается |
|--------|--------------|
| Игрок понимает, **где он** | Заголовок локации в рамке |
| Игрок видит, **что изменилось** | Маркеры `+` / `-` у счётчиков |
| Игрок не путается **в меню** | Отступы и нумерация пунктов |

> 💡 **Главное правило:** оформление служит читаемости, а не украшательству. Если после добавления рамки текст стало труднее читать — рамка лишняя.

## 📏 Приём 1: Разделители

Самый дешёвый и самый эффективный приём. Создаёт визуальные «стены» между блоками.

### Одинарные линии

```python
print("=" * 50)
print("-" * 50)
print("*" * 50)
print("─" * 50)
```

**Где применять:**

| Символ | Смысл |
|--------|-------|
| `=` | Начало/конец крупного блока (титул, финал) |
| `-` | Граница между ходами |
| `*` | Акцент на событии |
| `─` | Тонкий разделитель внутри меню |

### Двойная рамка (псевдографика)

```python
print("╔" + "═" * 48 + "╗")
print("║" + " Название ".center(48) + "║")
print("╚" + "═" * 48 + "╝")
```

**Метод `.center(n)`** выравнивает строку по центру отведённой ширины — удобно для заголовков.

### ⚠️ Важно про ширину

Длина строки должна быть **постоянной** во всём квесте. Если где-то `50`, где-то `40` — рамка «поедет», и вид будет сломанным. Зафиксируйте одно число для всей игры.

## 🔤 Приём 2: Эмодзи-маркеры

Эмодзи работают как иконки: глаз цепляется за них быстрее, чем за слово.

### Система маркеров

| Категория | Маркеры | Пример строки |
|-----------|---------|---------------|
| Ресурсы | 💰 ❤️ ⚡ | `💰 Монетки: 100` |
| Движение | 👣 🚶 🏙️ | `👣 Пройдено шагов: 5` |
| Локации | 🏛️ ☕ 🌳 🚉 | `📍 Локация: Центр города` |
| Предметы | 🎒 📱 🔑 🍎 | `🎒 В кармане: телефон` |
| Исход | 🎉 ❌ ⚠️ 💀 | `❌ Неверная команда` |
| Меню | 📋 📊 👋 | `📋 Что делаем?` |

### Правило последовательности

Выберите **по одному** маркеру на категорию и держите его до конца игры.

```
❌ Плохо:  Деньги: 100  /  💰 Монеты: 100  /  💵 Кэш: 100
✅ Хорошо: 💰 Монетки: 100  (везде одинаково)
```

### Совместимость

Не все терминалы одинаково рисуют эмодзи. Если работа сдаётся в консоли Windows (`cmd`), часть символов может превратиться в `?`. Два варианта:

- использовать эмодзи только в `print` описаний, а в служебных строках — обычный текст;
- продублировать смысл словами: `💰 Монетки: 100` → если `💰` не отобразится, слово «Монетки» всё равно всё объяснит.

## 🌬 Приём 3: Отступы и «воздух»

Пустая строка — это не «ничего», это пауза. Без пауз текст слипается в кашу.

### Пустая строка перед значимым событием

```python
print()
print("Ты вышла на центральную площадь.")
```

### Комбинированный переход

```python
print("\n" + "=" * 50)
print("НОВОЕ СОБЫТИЕ")
print("=" * 50 + "\n")
```

`\n` в начале даёт пустую строку сверху, в конце — снизу. Блок «дышит» с двух сторон.

### Отступ у пунктов меню

```python
print("Что делаем?")
print("  1. Идти вперёд")
print("  2. Осмотреться")
print("  3. Проверить статус")
print("  4. Выйти")
```

Два пробела перед цифрой визуально отделяют меню от вопроса — игрок мгновенно видит, где варианты ответа.

## 🗂 Приём 4: Карточка статуса

Вместо трёх разрозненных строк — один собранный блок. Это «HUD» консольной игры.

### Структура

```
╔══════════════════════════════════════╗
║           📊 СТАТУС ИГРОКА           ║
╠══════════════════════════════════════╣
║ 💰 Монетки : 100                     ║
║ ❤️ Здоровье: 100                     ║
║ 👣 Шаги    : 0                       ║
══════════════════════════════════════╝
```

### Что здесь продумано

| Деталь | Зачем |
|--------|-------|
| `╠══╣` под заголовком | Отделяет название карточки от данных |
| Двоеточия в одной колонке | Числа выстроены в столбик, читается быстро |
| Одинаковая ширина строк | Рамка не «разъезжается» |

### Задача на выравнивание

Чтобы двоеточия стояли ровно, подписи нужно привести к одной длине. Подумайте, какие строковые методы для этого подойдут — например, дополнение строки пробелами до нужной ширины.

## 🚦 Приём 5: Маркеры событий

Игрок должен за полсекунды понять: **повезло или нет**.

| Знак | Значение | Пример |
|------|----------|--------|
| `✅` | Действие удалось | `✅ Дверь открыта` |
| `🎉` | Награда / успех | `🎉 Бесплатный кофе! +20` |
| `⚠️` | Предупреждение | `⚠️ Монетки на исходе` |
| `❌` | Ошибка ввода | `❌ Я тебя не понял` |
| `💀` | Конец игры | `💀 Здоровье на нуле` |
| `💰+` / `💰-` | Изменение ресурса | `💰 -5 (проезд)` |

### Ключевой приём: показывать **дельту**

Игрок запомнил, что у него было 100 монеток. После действия ему важнее увидеть **сколько изменилось**, чем новое значение.

```
💰 Монетки: 95  (−5)
❤️ Здоровье: 100 (без изменений)
```

Одна скобка с дельтой превращает сухой вывод в понятную обратную связь.

## 📊 Приём 6: Прогресс-бар

Числа — это абстракция. Полоска — это мгновенно понятно.

### Принцип

Значение 0–100 делится на 10 ячеек: заполненные — `█`, пустые — `░`.

```
❤️ Здоровье: [████████░░] 80/100
💰 Монетки: [█████░░░░░] 50/100
```

### Логика построения (без кода)

1. Взять значение (например, `80`).
2. Разделить на 10 → получится количество заполненных ячеек (`8`).
3. Из десяти минус заполненные → количество пустых (`2`).
4. Склеить: скобка + заполненные + пустые + скобка + число.

### Где уместно

- Здоровье — обязательно (игрок должен чувствовать угрозу).
- Шаги до цели — хорошо (понятно, далеко ли ещё).
- Монетки — спорно, лучше просто число с дельтой.

## ⌨️ Приём 7: Печатающийся текст

Текст появляется не сразу, а символ за символом — создаётся эффект «живого» повествования.

### Идея

Выводить строку посимвольно с микропаузой между символами. Пауза задаётся функцией ожидания из модуля времени.

### Когда применять

| Ситуация | Применять? |
|----------|-----------|
| Титульный экран | ✅ Да, создаёт атмосферу |
| Кульминация сюжета | ✅ Да |
| Меню и статус | ❌ Нет, бесит при повторе |
| Валидация ошибок | ❌ Нет, игрок ждёт ответа сразу |

### ⚠️ Риски

- Игрок не может пропустить анимацию → раздражает на повторном прохождении.
- Если пауза слишком большая — игра «тормозит».
- Нужен отдельный режим: например, быстрая печать для меню, медленная — только для ключевых реплик.

> Для контрольной работы этот приём — **бонус**, не обязательное требование.

## 🖥 Сборка: как выглядит готовый экран

Пример того, как приёмы работают вместе. Это **образец вывода**, а не код квеста.

```
══════════════════════════════════════════════════
                   🏙️  ТВИНКС
            Большая жизнь в маленьком городе
══════════════════════════════════════════════════

📍 Локация: Окраина города
🕐 Время:   Утро, День 1

Ты вышла из автобуса с одним рюкзаком за спиной.
Вокруг шум, незнакомые улицы, незнакомые лица.

──────────────────────────────────────────────────
📋 Что делаем?
  1. Идти вперёд
  2. Осмотреться
  3. Проверить статус
  4. Выйти
──────────────────────────────────────────────────

Твой выбор: _
```

Обратите внимание, сколько работы здесь сделано без единой сложной конструкции:

| Блок | Приём |
|------|-------|
| Титул | Разделители `=` + выравнивание по центру |
| Локация и время | Эмодзи-маркеры + ровные двоеточия |
| Описание | Отступы, пустые строки до и после |
| Меню | Разделители `─` + отступ у пунктов |

## 🚫 Антипаттерны: чего избегать

| ❌ Так не делаем | Почему | ✅ Как правильно |
|------------------|--------|------------------|
| Эмодзи в каждой строке по 3–4 штуки | Текст превращается в шум | 1 маркер на категорию |
| Разная ширина разделителей | Рамки «едут», выглядит сломанно | Одно фиксированное число |
| Статус выводится всегда, везде | Игрок устаёт проматывать | По запросу (пункт меню) или раз в ход |
| Все сообщения без пауз слиты | Невидимо, что произошло | `\n` перед значимым событием |
| Цвета «в лоб» без контекста | Смысл неясен | Маркер + слово (`❌ Ошибка`) |
| Печатающийся текст в меню | Игрок ждёт мгновенного ответа | Быстрый вывод для служебного |
| Оформление раньше логики | Красиво, но не работает | Сначала Этапы 1–2, потом косметика |

## ✅ Чек-лист оформления

Отметьте перед сдачей контрольной:

- [ ] Ширина разделителей одинаковая во всей игре
- [ ] У каждой категории ресурсов — свой постоянный эмодзи
- [ ] Перед значимым событием есть пустая строка
- [ ] Пункты меню имеют отступ и нумерацию
- [ ] Карточка статуса выровнена (двоеточия в одной колонке)
- [ ] После каждого действия показана дельта: `+` / `−`
- [ ] Здоровье дублируется прогресс-баром
- [ ] Печатающийся текст (если есть) — только в ключевых сценах
- [ ] Оформление **не ломает** проверку ввода
- [ ] Игра одинаково читается и без эмодзи (смысл дублируется словами)

## 📌 Порядок работы

Оформление — это **косметика поверх работающей логики**. Не начинайте с него.

```
Этап 1: if/else  →  Этап 2: while/break/continue  →  Этап 3: функции
                                    ↓
                    Только здесь — оформление вывода
                                    ↓
        Этапы 4–6: строки, словари, файлы (оформление подтягивается по ходу)
```

Если добавить рамки до того, как работает цикл — вы будете отлаживать два сразу, и найти ошибку станет в разы сложнее.

> Подсказка: один про структуру экрана, второй — про обратную связь после действия.
